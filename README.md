# Лабораторная работа 1 — поиск лиц и глаз

Приложение **C# Windows Forms / EmguCV** для задания из методички «Основы работы с библиотекой компьютерного зрения OpenCV». Обнаруживает лица и глаза в потоке камеры компьютера и на фотографиях. Все параметры распознавания фиксированы.

## Как открыть в Visual Studio

1. Распакуйте весь архив в отдельную папку. Откройте **FaceEyeLab.sln**.
2. Нужны Visual Studio 2022 **17.12 или новее**, компонент **«Разработка классических приложений .NET»** и **.NET 9 SDK**. Проект проверен с Visual Studio 17.14 и SDK 9.0.319.
3. Дождитесь восстановления NuGet-пакетов. При первой сборке нужен интернет. Если восстановление не началось: ПКМ по решению → **«Восстановить пакеты NuGet»**.
4. Выберите **Debug | x64**, назначьте FaceEyeLab запускаемым проектом и нажмите **F5**.
5. Для просмотра кода раскройте проект в обозревателе решений. `MainForm.cs` содержит обработчики, вложенный `MainForm.Designer.cs` — разметку формы. Каскады находятся в `Assets/Cascades`.

Не копируйте один `.exe` отдельно от папки сборки. Для работы необходимы нативные библиотеки OpenCV и XML-каскады; Visual Studio размещает их автоматически. Устанавливать старый EmguCV 2.4 и изменять системный PATH по старым скриншотам методички не требуется.

## Как пользоваться

- **Запустить камеру** — открывает основную камеру компьютера (устройство `0`). Выбора источника или индекса в интерфейсе нет.
- **Остановить** — завершает захват и освобождает камеру. Последний результат остаётся на экране.
- **Открыть фото** — обработка JPG, PNG, BMP, TIFF.
- **Пример** — поочерёдно открывает два подготовленных изображения.
- **Сохранить PNG** — сохраняет текущее изображение с рамками, без исходного изображения и интерфейса.
- Зелёные рамки — лица, голубые — глаза. Внизу показаны количество объектов, время алгоритма и фактическая частота обновления потока.

Поток обрабатывается в фоновом задании, обновление Windows Forms выполняется в UI-потоке. Одновременно обрабатывается один кадр: очередь кадров не накапливается. Интервал таймера 33 мс задаёт частоту запросов, а не гарантированные 30 FPS.

## Фиксированные параметры

Одинаковые значения используются для фотографий и камеры. Поля и переключатели настроек удалены; изменить параметры во время работы приложения нельзя. Числовые константы находятся в `Models/DetectionSettings.cs`.

| Параметр | Значение | Назначение |
|---|---:|---|
| Шаг масштаба | 1,10 | Шаг пирамиды DetectMultiScale |
| Соседи | 5 | Минимальное число соседних обнаружений |
| Мин. лицо | 40 px | Минимальная сторона лица в уменьшенном кадре поиска |
| Искать глаза | Включено | Поиск не более двух глаз в верхних 65% каждого найденного лица |
| Улучшать контраст | Включено | Выравнивание гистограммы полутонового кадра |
| Зеркало | Выключено | Кадр показывается без отражения |

Открытие видеофайлов удалено из формы и из службы получения кадров. Поиск глаз и выравнивание гистограммы выполняются всегда.

Поиск выполняется на копии шириной не более 800 px. Рамки пересчитываются в исходное разрешение. Каскады ищут преимущественно фронтальные лица; поворот головы, тени, маленькое лицо, закрытые глаза и очки могут ухудшать результат. Программа обнаруживает объекты и не устанавливает личность человека.

## Где находится код

| Файл | Назначение |
|---|---|
| `Program.cs` | Вход в приложение и диагностический режим |
| `MainForm.cs` | Действия пользователя, таймер, фоновые задачи, обновление изображений |
| `MainForm.Designer.cs` | Элементы формы и их расположение |
| `Services/FaceEyeDetector.cs` | Подготовка изображения, каскады, поиск лиц и глаз, рамки |
| `Services/FrameSource.cs` | Захват только с основной камеры компьютера через VideoCapture |
| `Services/ImageFiles.cs` | Чтение изображений, включая кириллицу в пути |
| `Models/DetectionSettings.cs` | Неизменяемые числовые константы распознавания |
| `Models/DetectionResult.cs` | Результаты, координаты и владение Mat |
| `Diagnostics/SelfTest.cs` | Воспроизводимые интеграционные проверки |
| `Diagnostics/CameraDiagnostic.cs` | Проверка 10 кадров камеры без сохранения изображений |
| `Diagnostics/ErrorLog.cs` | Подробный журнал ошибки с именем функции OpenCV |

В методичке используется устаревший `Capture`. В текущем API EmguCV его роль выполняет `VideoCapture`. Вывод сделан двумя стандартными `PictureBox`, что позволяет обходиться без отдельного UI-пакета EmguCV. Алгоритм по-прежнему использует настоящую библиотеку EmguCV/OpenCV и XML-каскады Хаара.

## Сборка и проверки из PowerShell

Из корня решения:

```powershell
dotnet restore .\FaceEyeLab.sln --locked-mode
dotnet build .\FaceEyeLab.sln -c Release --no-restore
.\Test.ps1
```

Или откройте терминал PowerShell и выполните `./Build.ps1`. Если политика выполнения Windows запрещает локальные `.ps1`, используйте приведённые команды `dotnet`; менять системную политику не требуется.

Прямой запуск диагностики после сборки:

```powershell
$exe = '.\src\FaceEyeLab\bin\x64\Release\net9.0-windows\win-x64\FaceEyeLab.exe'
Start-Process $exe -ArgumentList '--self-test', 'TestResults' -WindowStyle Hidden -Wait
Get-Content .\TestResults\verification.json
```

Проверки используют нативный OpenCV: один портрет, два лица, координаты рамок, пустой фон, серый кадр, пустой Mat, отсутствие XML, кириллица в пути, повреждённый файл и обработка фотографий через форму. Проверки удалённого режима видео исключены. Результат последнего запуска находится в `docs/verification.json`.

Проверка камеры отдельно от интерфейса (изображения не сохраняются):

```powershell
$exe = '.\src\FaceEyeLab\bin\x64\Release\net9.0-windows\win-x64\FaceEyeLab.exe'
Start-Process $exe -ArgumentList '--camera-test', 'TestResults' -WindowStyle Hidden -Wait
Get-Content .\TestResults\camera-diagnostic.json
```

В текущем окружении физическая камера проверена на 10 кадрах: чтение, обнаружение и преобразование в Bitmap. На другом компьютере проверьте его камеру отдельно. Для визуальной проверки нажмите «Запустить камеру» и убедитесь в обновлении изображений и рамок. Если камера занята, закройте использующее её приложение.

### Если камера мигает и появляется OpenCV empty

Приложение сначала проверяет загрузку обоих классификаторов. XML читается средствами .NET и загружается в OpenCV из памяти; ошибка повреждённого каскада содержит имя файла. При каждой сборке и публикации XML-копии обновляются из исходников.

Камера считается открытой только после получения первого непустого кадра. Если DirectShow открывает устройство, но не дает изображение, приложение освобождает его и пробует Media Foundation. Для кратковременных пустых кадров предусмотрены повторные чтения. Разрешение и частоту кадров согласует драйвер; интерфейс выбора источника или параметров не добавлен.

Если ошибка повторяется, окно сообщения показывает имя функции OpenCV и путь к полному журналу: `%LOCALAPPDATA%\FaceEyeLab\error.log`. Журнал содержит стек ошибки, а не изображения с камеры. Результат `--camera-test` показывает этап сбоя и параметры успешно прочитанных кадров.

## Отчёт

`docs/Отчет ЛР 1.docx` подготовлен для первоначальной версии приложения: описание изменяемых настроек и открытия видео в нём относится к прежнему интерфейсу. Текущее поведение описано в этом README.
